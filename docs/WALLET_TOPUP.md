# 普通余额充值

用户总览顶部提供余额与充值入口，无套餐用户同样可以使用。任意金额从 10 元起，最多两位小数；微信、支付宝复用既有易支付商户配置，金额在接口中以整数分传输。系统整数存储上限为 2,147,483,647 分，创建支付和实际入账时均校验余额容量。

普通充值按实付金额入账，余额永久有效；不参加节日充值赠额或活动订单抽奖，也不触发普通套餐比例返利。活动期内新邀请好友首次满10元的普通充值，可按节日邀请规则向邀请人发放固定现金奖励及补足邀请抽奖次数；关闭时新建充值不获得活动资格，关闭前已冻结资格继续兑现。节日充值仍从独立活动入口参加，避免将任意金额充值误认为活动档位。

## 接口

以下接口要求已登录身份，使用服务端身份确定账户，不能指定其他用户。

- `POST /api/portal/wallet/topups`：`{ amountCents, paymentType: "alipay" | "wxpay" }`，必须带 `Idempotency-Key`（最长 100 字符）。同一标识绑定金额及渠道，重复提交返回原支付。
- `GET /api/portal/wallet/topups`：最近五次充值支付状态。
- `GET /api/portal/wallet/topups/:id/checkout`：恢复本人未过期支付入口；已结束订单只返回状态。
- `GET /api/portal/payments/epay/:id`：沿用既有状态查询。
- `GET /api/portal/wallet`：沿用既有余额、流水查询。

支付尝试快照为 `{ version: 1, purchaseMode: "wallet_topup" }`，不挂靠虚拟套餐。商户凭据、金额和渠道冻结。验签成功后，在 Serializable 事务内创建 `WALLET_TOPUP` 订单、真实支付记录和余额账本，再标记履约完成。新请求替代旧支付，旧链接迟到款项走原路补偿；仅超时而未替代的充值可核验后正常入账。重复回调不重复入账。

退款仅允许全额原路退款，先在同一事务中追回余额并登记待退款账单及网关任务，网关确认后账单变为已退款。余额不足时拒绝自动退款，需人工处理；不重复退入余额，不形成负余额。失败原因沿用支付异常队列展示。

复用节日功能已新增的 `WALLET_TOPUP` 枚举，无额外数据库迁移；部署时必须包含节日迁移。开发验证使用独立本地 `holiday_test` 数据库，`wallet-topup.e2e-spec.ts` 覆盖签名、渠道、金额、并发、幂等、用户隔离、过期续付和退款。真实网关付款需在配置正确的环境另行联调，单元及事务测试不会请求外部网关。
