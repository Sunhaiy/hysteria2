# 补差价升级

仅在用户端「套餐」页面的购买抽屉提供「补差价升级」。后台及其他页面不提供
补差价升级入口或后台专用接口。支持普通月付、季付、年付同周期向上升级，
用户可使用余额、支付宝或微信。

购买报价返回服务端核验的 `canUpgradePlan`，仅对当前有有效普通套餐、所选同周期
更高价套餐且满足升级规则时显示入口；无套餐、同价、低价、同套餐不显示。
已购预约套餐经后台提前启用后，按审计记录中的实际生效区间核价，保留原支付快照。
审计记录必须对应同一用户、权益、订单、周期及新旧到期时间，不凭日期差异猜测。

## 金额和权益

- 目标剩余价格 = 目标同周期售价 × 剩余毫秒 / 原购买周期实际毫秒。
- 原套餐抵扣 = 原订单实付金额 × 同一剩余比例。使用整数计算并四舍五入到分。
- 后台免费发放（ADMIN、实付为零）的套餐，使用原订单 `basePriceCents` 标价快照
  按剩余时间抵扣；不使用后续目录改价，不改写原订单实付或增加现金收入。
  缺少有效标价快照仍需人工核对。报价和升级订单记录抵扣依据，页面注明赠送抵扣。
- 新报价应付 = 目标剩余价格 − 抵扣 + 500 分升级手续费。手续费每次升级固定收取，不按时间折算，也不计入下次升级的可抵扣价值。优惠订单不会按未折扣价格抵扣。
- 历史已完成订单不追收；变更前已签发的有效报价和已创建付款订单沿用原金额，避免付款中途加价。新报价单独展示手续费并写入升级快照。
- 再次升级以上一次升级的剩余价值为抵扣基础，避免重复抵扣最初实付。
- 保留同一 grant、订阅、到期日、周期锚点和历史账本；本期仅增加套餐额度差额，
  不清空 consumedBytes。独立流量包、永久 Ultra 和奖励不变。
- 新套餐访问权限、速率、设备限制同步到当前权益；用户和机器倍率不变。
- 升级不发起新邀请返利、拼团奖励或活动抽奖。

## 报价与一致性

报价使用现有 SETTINGS_ENCRYPTION_KEY 的 AES-GCM 加密认证，绑定用户、原权益、
订单状态、额度周期和目标商品快照。客户端不能修改金额或延长报价。
有效期最多 15 分钟，且不超过当前周期或套餐结束时间。
普通流量消费不会导致报价失效；续期、切换、额度调整、周期切换等会触发重新报价。
余额扣款、订单、权益差额和审计在同一 Serializable 事务中提交。
外部支付复制报价到支付快照；不满足履约条件时沿用补偿退款流程。
同一幂等键不能改变支付渠道、目标商品或报价；重复到账不重复加额度。

## 首版人工处理边界

无普通套餐、多个当前权益、有预约、存在退款、无有效标价快照的赠送套餐或 CDK、拼团套餐、
多笔续期组成的有效期、无法核对完整付款周期、人工更改有效期、降档、跨周期
购买都不自动核算，明确提示客服处理。升级关联原订单与补差订单不能单笔自动
退款，需要合并人工核算，避免重复退回已抵扣价值。

## 验证与发布

新增 nullable `ManualOrder.planUpgradeSnapshot`，不修改历史用户数据。
发布前先执行新增迁移，再切换候选 API/Web；无需重启节点。
本次开发不连接生产、不自动部署。

相关 Jest 覆盖金额、月末/闰年、报价篡改、冲突及额度更新；真实 PostgreSQL
测试使用独立本地 `upgrade_test` schema，不接受远程数据库：

```
pnpm --filter @hysteria/api build
# 在已设置本地 DATABASE_URL 并完成 prisma db push 的环境中：
node apps/api/test/standard-plan-upgrade.integration.cjs
```

该测试覆盖两种并发幂等情况、余额不足回滚、支付宝/微信支付尝试创建、已验签
付款履约、重复回调、迟到付款补偿和退款拦截，不会调用真实收款或退款网关。
